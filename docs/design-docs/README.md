# Design docs

Durable design notes and "core beliefs" — the *why* behind non-obvious choices.
Reach for a design doc when a decision needs context that won't fit in a code
comment and should outlive any single PR.

- One file per topic, kebab-case (e.g. `effect-system.md`).
- Lead with the problem and the decision; alternatives considered are a plus.
- Link to the code and to [`../architecture.md`](../architecture.md).

The deepest existing design reference is the engine guide,
[`../../back/app/game/README.md`](../../back/app/game/README.md).
